# Testing and evaluation

Moved out of CLAUDE.md on 2026-11-11 so the file every session loads stays short; CLAUDE.md keeps a summary and points here. This is the full reference: the unit, robustness and browser suites, CI, and the eval tooling (scripted conversations, direction metrics, the AI review). Every rule carries the reason and the date it was added. Keep it current with `bot.py`: a new rule gets its line here, with why and when.

`tests/test_guards.py` (stdlib `unittest`, run with `.venv/Scripts/python -m unittest discover -s tests`) covers the guarantees that live in code: consent, redaction, lead routing, the output gate, `max_tokens`, price provenance, the fit check, the audit, the spend caps and API-error handling, the size caps, the web demo's limits (Flask test client), and retrieval quality on `tests/retrieval_golden.json`. `tests/test_robustness.py` (metamorphic, no model, about 5 s) multiplies phrasings of what code reads from the customer — areas, rooms, the cheap / filtration / quiet / Wi-Fi wishes, a complaint or a sale, a price question, the consent answer, "choose for me" — by meaning-preserving transforms (no diacritics, case, a greeting, no punctuation, spacing, every unit form) and expects the same reading; `python tests/test_robustness.py --report` prints a table. Its first run (2026-11-09) failed 163 of 2 280 variants: `no_re`'s closing `\b` kept "nechcem … údaje" from being a refusal, "Váš" missed the complaint pattern, a negation after the wish ("Wi-Fi nepotrebujem", `_NEGATED_AFTER_RE`) wasn't seen, the complaint and installation patterns are now also matched without diacritics (`_COMPLAINT_FOLDED_RE`, `_OUR_INSTALL_FOLDED_RE`, `_FAULT_FOLDED_RE`), and Wi-Fi triggers take any spacing. A new phrasing that code must read belongs in a family there. **Browser tests** (`tests/e2e/`: `test_chat.py`, `test_accessibility.py` and `test_mobile.py`, pytest + pytest-playwright, Chromium; `pyproject.toml` points `pytest` at them and keeps a trace and a screenshot of a failed test in `test-results/`, gitignored; about 15 s): the real `web.app` runs in a thread on a free port, with `test_guards`' `FakeClient` as the model (they import `test_guards`, so logs and leads go to its temp dir and the PM mail is off). Between tests the client is `_NoModel`, so a call nobody scripted fails instead of reaching the API. A `ChatPage` object holds the locators (by role and accessible name, except the chat bubbles, which have none). Every test starts on a fresh server (`fresh_server`: no visitors, rate-limit hits or spend) and fails on a server exception (`web.log` at ERROR), a JavaScript or console error, or a request to another host (`guard_page`). `model.replies(...)` scripts one reply per model call; a regeneration needs its own (the spelling check regenerates a reply full of HTML once). The tests cover the welcome suggestion → the offer with two price cards → "Toto chcem" → contacts → the consent button → the PM record (downloaded, with `cost_report`'s GDPR audit `ok`); a refusal; sanitizing (the server lets HTML through, so DOMPurify is the last defence); a reload resuming the conversation; the reset dialog; an API error; the composer; the 👍 reaching the log; and a phone viewport (tabs, the toast for the PM record). When the page changes, keep the roles and names they find it by, or update `ChatPage`. Each test was checked to fail when the page was broken the way it guards against (2026-11-09). **Accessibility** (`test_accessibility.py`): axe-core (the pinned copy in `axe-playwright-python`, run with `page.evaluate`) scans the welcome page, the offer, the PM record, the reset dialog, the dark theme, the debugging view and the phone layout against WCAG 2.2 A/AA and axe's best practices and fails on any violation; the scans run with reduced motion (the page honours it), because a bubble fading in reads as a contrast failure. Its first run (2026-11-09) found grey text at 4.3–4.4:1 (`--text-3`, now `#5b6b80`), white on `#0284c7` in dark mode (`--accent-strong` now `#0369a1` in both themes), the demo banner and, on phones, the tab bar outside every landmark (the banner is an `<aside>`, the tablist sits inside the `<nav>`, whose landmark its role had replaced) and price cards that were all one landmark name (each card is named after its lines). Two keyboard tests: Tab reaches the message box, Enter sends and the focus comes back, and the phone tabs follow the arrow keys. Keep the page at zero violations: a new element needs a role or a name the scan accepts. `.github/workflows/tests.yml` runs the unit, robustness and browser tests on every push to main and every PR (Python 3.13 as in the Docker image, CPU-only PyTorch, the models and the KB embeddings cached, no key). The model is replaced by a `FakeClient` that replays scripted responses or raises scripted SDK errors, and fails on any `tool_use` sent without its `tool_result`, a misplaced system message, or a thinking block sent back after anything before it changed (the API's history-editing check, `check_thinking_prefix`); no key or network needed, but importing `bot` loads the embedding model. On Windows set `PYTHONIOENCODING=utf-8` when the output is piped (the bot prints Slovak text). `eval/run_eval.py` raises the spend caps by default (the CLI's usage figures carry its own overhead); set `KLIMABOT_SESSION_USD_CAP` to test them. There is no linter config and no build step. `eval/test_scenario.py <name>` drives a scripted conversation through the live API (needs the key) and prints the transcript with validator events; it makes no assertions. `eval/` runs scripted customer conversations with the local Claude Code CLI (`eval/run_eval.py --scenarios …`, then `eval/analyze.py <run dir>`), or with `--api` against the real API with the production caps on and a run budget (`--budget-usd`, default 10; the key must be real — bot.py refuses the `.env.example` placeholder). `eval/scenarios/boundaries.json` covers the boundaries (off-topic, medical, "are you human", staff data, smoke, English sparks); a scenario's `must_say` (`[{"turn": 1, "pattern": "112"}]`) requires a pattern in that turn, next to `must_not_say`. `eval/scenarios/qa_csat.json` replays the customers' messages of the QA of 2026-11-01 (docs/qa_csat_2026-11-01.md). `eval/scenarios/redteam.json` holds the adversarial ones (Safety → Red team). `eval/scenarios/abuse.json` holds the cost-abuse conversations (tool-loop injection, 50-code compare, long message, state stuffing, handoff spam, a 24-question marathon). `analyze.py` reports cost per conversation (from the `llm_turn` events), the cache-read share, conversations that hit the cap and each scenario's `max_usd`. **Direction metrics, on every commit** (`eval/stability.py`): the scripted conversations of `eval/scenarios/direction.json` — per turn the customer's message, the move the conversation policy should pick (`expect`) and how the bot should answer (`should`), per conversation the final output checked by code (`final`: quotes, a price shown or not, lead, consent, regexes on the replies) — run several times (`--reps`, default 2) through the Claude Code CLI on the subscription by default (`--api` opts in to the paid API with `--budget-usd`; the owner doesn't want test runs on the API). Metrics: on target (the reply heads where the script says, `direction()` read by code — since 2026-11-01 a quoted price next to "v podkladoch nemám" is an offer and an imperative "povedzte mi…" counts as a question; since 2026-11-07 a price in "EUR", a question put as "…dôležité:" before a list and an offer that shows an earlier quote again count too, and the thanks after consent may recap the price — so on-target rows before those dates read lower), policy correct (`next_move()` picked the expected move), model followed (the reply did what its move said), repeats agree, final OK, regenerations / calls / seconds per turn and USD per conversation (CLI figures: comparable between commits, not with production). `--commit SHA` measures a commit in a temporary worktree (one run at a time, a lock) and appends a row to `eval/runs/metrics/history.jsonl` (gitignored, local), with a `report.md` per run; `--history` prints the trend; `--install-hook` writes a git `post-commit` hook that does this in the background for every commit (`KLIMABOT_METRICS=0 git commit …` skips one). `--model` and `--effort` run another model on this checkout through the CLI, priced at its own rates in `model_prices.json` and left out of the history. Haiku 5.5 thinks there whatever the switches say (`MAX_THINKING_TOKENS=0` and `--thinking disabled` don't stop it, `modelUsage.thinkingTokens` in `cli_calls.jsonl`, checked 2026-10-30), as production's customer turn does since 2026-11-05 (HyDE and the summary, without thinking in production, think there); the adapter passes the request's `output_config` effort on unless `--effort` overrides it. Rows from before the switch to Haiku 5.5 aren't comparable with later ones, and rows from before 2026-11-05 ran at the CLI's default effort. `DirectionScenarioTests` checks every scripted turn's move against `next_move()` without a model. The CLI adapter (`eval/claude_cli_client.py`) emulates `tool_choice` `none` and `any`, and both runners pass the production model ID. `eval/judge.py <run dir>` is the AI reviewer: a model (Haiku by default, `--model` only with prices in `model_prices.json`; `--cli` runs it through the Claude Code CLI on the subscription, no budget — the adapter reads its `tool_choice` `tool` as `any`) scores each conversation 1–5 on discovery, wishes, sizing, grounding, language and flow against the owner's rules (`CRITERIA`), with findings per turn, into `judge.md` / `judge.json` (`--only c01,c03`, `--budget-usd`, default 1; about $0.01 per conversation). It catches what the regexes can't — no question about which rooms, "najlacnejšie" answered with a premium series, repeated questions. Its tool schema is flat because Haiku sent a nested object as a JSON string; `normalized()` still parses string-encoded values. The bot is a single-file CLI (`bot.py`) with a Flask web app (`web/`).

## Changed 2026-11-11

- `tests/e2e/test_mobile.py` (the redesign of the web page): a headless browser has no on-screen keyboard, so `FAKE_KEYBOARD` replaces `window.visualViewport` before the page runs and `window.__keyboard(height, top)` plays iOS Safari's keyboard (the visible part shrinks and pans down to the message box). The test checks that the app fills exactly that part, the header and the message box inside it, the latest reply in view, the tabs hidden and the demo notice shown, and that closing the keyboard restores it. `test_small_phones_never_scroll_sideways` resizes a phone with two price cards to 320, 360, 375 and 412 px and fails on anything wider than the screen; `test_a_reload_does_not_replay_the_entrances` counts the animations in the log after a reload. Each was checked to fail on the page broken the way it guards against (no viewport fit, replayed rows animated, a price card with a fixed minimum width; a fixed width alone shrinks in its flex row and isn't a break). Their first run found that hiding the tabs while the message box had the focus moved the consent button away under a click (the blur comes before the click), so the tabs follow the keyboard instead. `test_a_short_phone_opens_the_welcome_card_at_its_top` came after the first deploy: a screenshot of the live page on a 390 × 844 phone showed the welcome card scrolled past its logo, because `fitViewport()` kept "the latest message" in view on load; it fails without the fix. `WebTests` also checks that both font files are served as `font/woff2` (the slim image served `application/octet-stream`; Python 3.14 on the workstation knows the type, so that assertion can't fail there).

- `eval/run_eval.py` keeps each tool's full result (`output`, matched to the 300-character `output_preview` of the `tool_result` event, `_attach_full_outputs`), and `judge.py` shows the reviewer up to `TOOL_PREVIEW_CHARS` (4 000) characters of it. With 400 characters of a five-size `lookup_product` the review flagged correct dB figures as wrong (c16, c20 of the A/B of 2026-11-09). Review scores from runs before this aren't comparable on grounding.
- `eval/scenarios/boundaries.json`: b05 expects today's complaint handover (details and the complaint consent question, no promises) instead of "company contact only, no data", which predated 2026-11-01.
- `NoiseFigureTests` and `RedTeamLeftoverTests` cover the 2026-11-11 changes; each test was checked to fail on the code before them.
