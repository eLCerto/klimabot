# Customer state, prompt caching, server context and conversation policy

Moved out of CLAUDE.md on 2026-11-11 so the file every session loads stays short; CLAUDE.md keeps a summary and points here. This is the full reference: how a request is built (tools → system → conversation → server context), why a turn's requests are append-only, what the server context carries, and every move of the conversation policy with its triggers. Every rule carries the reason and the date it was added. Keep it current with `bot.py`: a new rule gets its line here, with why and when.

The customer state (`S().customer_state`, still called CUSTOMER_STATE in comments and tool descriptions) is mutated by `update_customer_state` (deep-merge: lists union, `None` removes keys; `updates` sent as a JSON string is parsed, trailing junk ignored — the model does that sometimes; it returns only the changed field names and drops writes to `consent_*`) and by code for consent and the phone/e-mail safety net. **Prompt caching and the server context.** A request is tools → system → conversation → server context. `build_system_blocks()` returns only the persona prompt and the `CRITICAL_RULES_TEXT` checklist, identical on every call, with a cache breakpoint on the checklist. `_messages_for_api()` sends the stored history the same way every call (customer text as a text block), then the turn so far, with a second breakpoint on the last block of the final user message, so each call reads the conversation the previous call cached. **A turn's requests are append-only** (`turn_api` in `run_user_turn_streaming()`): each tool round goes back as the API saw it — the user message with the server context it was sent with (`_with_context`), the response (whole when it carries a thinking block, which goes back unmodified together with any text hidden next to the tool call; without one only its tool calls, as before), the tool results — because a Haiku 5.5 thinking block is valid only while the system prompt, the tools and every message before it are unchanged (a 400 for accounts created after 2026-08-31; moving `cache_control`, `tool_choice` or `max_tokens` doesn't count). The stored history keeps none of it, so a turn starts with no thinking blocks to check (dropping the leading ones is allowed) and the context grows only by what the customer saw. A regenerated draft is never sent back. Measured on the real API on 2026-11-05: the server context as a mid-conversation system message cost the cache across turns (the next turn read only the system prompt), and sending each turn's API copy in later turns nearly doubled the context (96k tokens after five turns) without getting the cache back — a long conversation hit the $0.07 cap at $0.041 and lost its lead. Everything that changes per call — first the **move** of the conversation policy (below: one direction per customer turn, "ĎALŠÍ KROK"), then the form of address ("Oslovenie: vykaj", or tykaj when the customer tyká — `_customer_tyka`; said up front, not only checked by `vykanie`; for a customer who tyká the directive's example sentences in „…“ are turned into tykanie, `_as_tykanie` — copied in vykanie they made `oslovenie-mix` the top rewrite, 5 → 11, in the API A/B of 2026-11-08), the customer state (compact JSON, headed as data written from the customer's words, not instructions), the consent status, the filtration ranking, the colour variants from the price lists when the customer mentions a colour (`_colors_text`), a note against resizing for sun, overheating, insulation or an attic (`_SUN_HEAT_RE`), the session language (Slovak only, the owner, 2026-11-09: an English-writing customer gets "odpovedaj VÝHRADNE po slovensky" and, once, code's `_OTHER_LANGUAGE_NOTE` "I can reply in Slovak only." — `_writes_english`, `_other_language`; `_session_language()` always returns "sk" and the old "en" branches are dormant), the 80 % budget note and a regeneration note — is `build_server_context()`: a `<server_context>` text block of its own appended to the final user message after the breakpoint and never stored in the history (the latest one counts, the checklist says). A tag the customer types is defused (`<server-context`), the checklist tells the model the block is the server's, and the validator flags it in replies. The eval's CLI adapter renders the block as is. Because the state is re-sent on every call, `update_customer_state` clips strings to `STATE_MAX_STRING` (300) and lists to `STATE_MAX_LIST` (20), and refuses an update that would take the whole state over `STATE_MAX_CHARS` (4 000). **Conversation policy** (section "Conversation policy", diagram and table in [docs/conversation_policy.md](docs/conversation_policy.md)): `next_move()` decides once per customer turn, when the message arrives, where the reply heads, and the first case that applies wins — `bezpecnost` (`_DANGER_RE`), `reklamacia` (`_support_case`), `priemysel` (`_industrial_case`), `vlastna-montaz`, `odvolany` (consent withdrawn: nobody will call, and the reply may not say otherwise), `zapis` / `po-zapise` (sales consent recorded), then the sale (`_sales_move`): without a quote `zisti-priestor` (no m², kW or code), `zisti-izby` (a multi-room flat — "dvojizbový", "2-room flat", `_FLAT_ROOMS_RE` — until the customer answers which rooms, `_ROOMS_ANSWERED_RE`, or names one, `_ONE_ROOM_RE`: "len do spálne", "obývačku nechám tak"; asked once, also when `zisti-priestor` already asked, `_ASKED_ROOMS_RE`: the senior of the QA said "len spálňa" four times), `zisti-priority` (size known, no price question, no wish, not asked yet: `_offer_due`, `_preferences_known`; asked once more when the customer's reply to it only gave or corrected the rooms' sizes, `_priorities_unanswered` — the owner, 2026-11-09 — and a second unanswered question brings the offer), `ponuka` (two options, each priced by `quote`; the two sets picked by code when `_suggested_sets` finds them, never for a salon, a practice or a server room, where `quote` refuses residential sets (a server room got two refused code quotes and 4–7 calls of recovery, API A/B of 2026-11-08) — one per brand, white, the smallest size covering the m², tier-1 filtration for "the best" or an allergy, Wi-Fi as standard when wished, single-room wall-unit requests only, `_picks_text`; for 2–5 rooms multi-splits picked by code, `_suggested_multis` / `_multi_picks_text`: per brand the cheapest white wall series with a unit for every room, the smallest that covers it, and the smallest outdoor unit that carries them, with Wi-Fi, a named brand and "the best" respected, one size per room from `_room_sizes()`, which keeps repeats; a request code can't read falls back to `lookup_product`); after a quote `kontakt` (an offer picked, `_chose_offer`: `_OFFER_CHOSEN_RE`, `_OFFER_CHOSEN_FOLDED_RE` on what stands after the message's last change of mind, `_last_word` — "tá lacnejšia mi stačí", "nech príde obhliadka", "beriem Samsung", "Nie počkajte, radšej tú Toshibu" — but not "Beriem Luzon. Vlastne nie.", a wish, "chcem tú najlepšiu, čo máte", a condition, `_NOT_A_CHOICE_RE`, or a size or finish no quote has, `_unquoted_spec`; or contact details typed, which `_CONTACT_GIVEN_TEXT` doesn't ask for again), `nova-ponuka` (a cheaper / other variant asked for, `_NEW_VARIANT_RE` — "tá lacnejšia" only points at an offer, "čo najlacnejšie" asks for the cheapest variant, "čo keby multisplit Toshiba", "koľko je nástenná", "niečo krajšie" ask for another one — a price question, a code, series or size), `odpoved` (a question), `pokracuj` (also a customer leaving or thinking it over, `_LEAVING_RE`, with or without a quote: no offer, no contact request; "zabudnite na obývačku" isn't leaving; and, before any sale, a request for the company's contact or for staff details, `_CONTACT_ONLY_ASK_RE`: the company contact, no question about the space — b04 got `zisti-priestor`). Every sales move also gets `_questions_note()`: the customer's own questions of the latest message, quoted, to answer before anything else (a short question about the price alone is left out), with what code knows — all models heat, the recycling fee is on top, nothing in the documents about pets, permits go to the PM (a tenant asking directly about the landlord's consent is told to check the lease or ask the landlord, the PM assesses the technical side; the owner, 2026-11-01), dB from `lookup_product` for both units. A customer who wants a person (`_HUMAN_WISH_RE`) gets a note: the PM calls back, as a condition, or the contact (`_human_note`); before consent so does one who asks whether someone will call ("Zavolá mi niekto?", "kto nás bude kontaktovať?", `_CALLBACK_ASK_RE`: "Keď odsúhlasíte otázku nižšie, projektový manažér sa vám ozve…", or "Ak mi necháte meno…" without a contact), and the `reklamacia` move after the details were asked gives the conditional sentence for what comes next, as does the first `reklamacia` reply to "Môže sa mi niekto ozvať?". A "súhlasím" in the latest message that recorded no consent (typed before the question, or without one) puts "SÚHLAS ZATIAĽ NIE JE" into the server context (`_early_yes_note`): the model took it for consent — "údaje som si zapísal" was 4 of the 9 `slub-bez-suhlasu` rewrites in the API run of 9657449, all on complaints. A price question counts from any earlier message while no quote exists. A budget adds `_budget_note()`. Instalments, photovoltaics or a technology the knowledge base never mentions in the latest message wrap the sales move as `neponukame` (`_decline_text`: the exact sentence to say — "Na splátky ani na leasing nepredávame.", "S fotovoltikou neponúkame nič…", "O … v podkladoch nemáme informácie…", neutral to tykanie and vykanie, nothing more about it — then "Potom:" the sales move, whose prerun and `tool_choice` it keeps — dropping them left a directive saying the server had priced options nobody priced; a free-worded decline added "…bankový úver, ktorý si môžete riešiť sami"). The directive is the server context's first line; the move is kept for the turn in `Session.turn_move` (a quote made mid-turn mustn't flip it); the customer's message joins the stored history before `next_move()` runs, so `_previous_reply()` is the bot's last reply (it read the one before until the A/B of 2026-11-09, and the priorities re-ask never fired live); **Code prices the offer it picked itself** (`Move.prerun`, since 2026-11-07: the model spent a thinking round fetching those prices, and offer turns were the slowest, 12–14 s at the median): when `ponuka` has code-picked options — `_suggested_sets` (each set's `quote` and `lookup_product` '<series> <kW>', `_picks_prerun`), `_suggested_multis` (their `quote`) or the cheapest room sets of one brand (one `quote`, `_room_sets_prerun`) — code runs those tools before the first call (`tool_call` / `tool_result` events and log lines with `prerun: true`, event `offer_prerun`). The results reach the model in the server context (`_turn_prerun`, "VÝSLEDKY SERVERA", right after the directive, whose wording says they are priced, `priced=True`) and the stored history as a tool round (dict blocks, `toolu_server_…` ids), so later turns see the codes like any other round; this turn's request doesn't carry that round (it holds only the model's own rounds, whose thinking stays valid, and whether the API accepts a code-written `tool_use` round without a thinking block in a thinking turn isn't documented). The same call made by the model is a `repeat_lookup`. With two priced options the first call is `auto`; a refused code quote (its `CHYBA` in the block) or only one priced option keeps it `any`. `ponuka` without code picks and `nova-ponuka` make the turn's first call `tool_choice: any`; both carry `_EXACT_AMOUNTS` (amounts exactly as `quote` returned them — no rounding, sums or multiplying — and only `series_features` claims: after the policy, amounts not from quote and unsupported claims were what still regenerated); the gate demands a price (`cena-neodpovedana`) only on those two moves; when the reply shown on an offer move, `odpoved` or `pokracuj` states none of this turn's quote totals (cut sentence by sentence or regenerated twice), code adds them, one line per quote before the closing question (`_offer_prices_text`, `offer_prices_appended`); the first offer asks for no contact yet; on the discovery moves a `quote` call is refused with an `is_error` result (`limit_hit` `discovery_quote` — refusing only quote keeps lookups and `update_customer_state`, which `tool_choice: none` would have cut); each turn logs `policy_move`. A size the customer doesn't know ("neviem koľko m2", "odhadnite vy", `_SIZE_UNKNOWN_RE`) counts as known: `ponuka` prices 2.5 kW sets as an estimate the PM confirms. "Dom má 120 m2" alone names no rooms: `zisti-izby` asks once (`_ASKED_ROOMS_RE`), then `ponuka` prices one room as an example. A server room skips `zisti-priority`; a commercial place is asked about the ceiling, tichý chod, filtration and price, not Wi-Fi or design (an office the same without the ceiling). Six or more rooms add `_rooms_limit_note` (five indoor units per outdoor unit, two systems, each its own `quote`). A cheap wish with two or more rooms leads with the cheapest separate sets (`_cheapest_room_sets`, `_room_sets_text`: the same set counted, one `quote`) unless the customer asked for one outdoor unit, on `ponuka` and, for a cheaper variant, on `nova-ponuka` (`_cheapest_rooms_text`); a customer who asks which is cheaper, separate sets or a multi-split (`_MULTI_VS_SETS_RE`), gets both priced by code on `ponuka`. After an offer a question about a spec (`_SPEC_QUESTION_RE`: dB, SEER, warranty, "čo je…") is `odpoved` even with a series named; with two or more quotes, a comparison of them that names no new code, series, m² or kW and asks for nothing else once the comparison is blanked ("Ktorá varianta vyjde lacnejšie a o koľko?", "o kolko je ta drahsia?", "cenový rozdiel", "koľko zaplatíme pri každom", `_QUOTED_COMPARE_RE`; not "…a máte niečo ešte lacnejšie?") is `odpoved` too, answered from those quotes — "koľko" sent it to `nova-ponuka`, whose gate demanded a new quote (A/B of 2026-11-07); so is a question about the installation's price after an offer ("A koľko bude montáž?", "koľko to bude aj s montážou?", `_INSTALL_PRICE_ASK_RE`, `_INSTALL_ANSWER`: the PM prices it after the free site visit, no estimate, no range) when nothing else is asked — it went to `nova-ponuka` in every arm of the API A/B of 2026-11-08; "Beriem Avant Black" is `kontakt` for a quoted series (`_chose_quoted_series`); agreeing to an offer ("pripravte ponuku", "tak dve") is `nova-ponuka`; the price of an offer already shown asked again with nothing new — only price words and filler, the same rooms and areas, a shown quote covering every room ("Prosím vás, povedzte mi už tú cenu, píšem to tretíkrát", `_price_asked_again`) — is `odpoved` with `_PRICE_AGAIN_TEXT`: the price of the option that fits best, in at most three sentences, without the second option (d03 got both in full three turns running, API run of e695916). From `nova-ponuka`, `odpoved`, `kontakt` and `pokracuj` on, the server context lists the offers so far with their totals once there are two (`_offers_so_far_text`, "PONUKY Z TOHTO ROZHOVORU"). `nova-ponuka` and `odpoved` ask for no contact until the customer chooses (`_NO_CONTACT_YET`), and discovery moves name no kW. A contact request left in a `ponuka`, `nova-ponuka` or `odpoved` reply is removed (`_drop_contact_requests`, `contact_request_dropped`), and "Ak sa rozhodnete, požiadam vás o meno…" isn't a request (`_CONTACT_LATER_RE`), so no consent paragraph follows; on `kontakt` it counts. A complaint next to a wish for a new unit with a known size keeps the sale going (the directive opens with the complaint's and the sale's prerun is kept, `_new_unit_wished`: "koľko by stála ešte jedna klíma do detskej izby" too, not "Novú klimu nechcem"). The server context also covers a non-VAT-payer (`_NON_VAT_PAYER_RE`: the price with DPH is what they pay), refrigerant (`_REFRIGERANT_ASK_RE`: not sold, a certified installer or the company) and a language we don't answer in (`_other_language`: Cyrillic, Hungarian and, since 2026-11-09, English; code prepends `_OTHER_LANGUAGE_NOTE` once). Before the policy the server context carried up to a dozen independent notes and about half the demo's regenerations were wrong-direction drafts. Measured with `eval/stability.py` (the same scripted conversations three times per version, each reply's direction read by code, `--compare`): see the commit that added it for the numbers. `discounts.json` is deliberately **not** in the prompt — percentages the model can see are percentages it is tempted to apply itself. The segment triggers it needs are generated into `quote`'s tool schema by `_segment_guide()`.

## Added 2026-11-11

- A request for another language adds a note: the server appends the sentence, the model doesn't mention languages (docs/output_gate.md).
